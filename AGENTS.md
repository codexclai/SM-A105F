# Project instructions

## Codex CLI operating rules

- Use the project-scoped launcher `scripts/codex-task.sh` for Codex CLI work. It accepts only models and reasoning efforts present in the installed CLI's live catalog, explicitly sets the chosen model/effort for that task, and runs with the workspace-write sandbox and on-request approvals. Project default is `gpt-6-luna` at `low`; use only `gpt-6-*` models. Select a stronger GPT-6 model or effort only for a task whose uncertainty, integration complexity, or consequences justify it. Use separate sessions for materially different model/effort assignments.
- Before substantive work, inspect the actual task and assigned model/effort. If a running task materially needs another GPT-6 model or effort, interrupt it (Esc), leave its working tree intact, report the exact recommended assignment to the supervising Work session, then let that session start a separate launcher invocation at the new assignment if usage permits. Do not wait for user model switching while Codex CLI is available. The launcher records the assignment explicitly. It cannot verify another application/chat's model, enforce model identity after a person changes `/model`, authenticate accounts, or inspect account usage limits. Do not claim otherwise. Check CLI `/status` at the start of a session and when usage is becoming constrained; follow its displayed remaining allowance and reset time, since the account may have both rolling and weekly limits. The user reports a five-hour reset window; do not assume it is the only active limit or infer reset times. If usage is exhausted, stop starting Codex tasks and report the displayed reset time; do not buy credits, switch to API-key billing, or upgrade a plan. Do not use API-key authentication or switch to non-GPT-6 models for this project.
- Start each fresh session by reading `Prompt.md`, `START_HERE.md`, this file, `docs/STATUS.md`, `docs/JOURNAL.md`, `docs/SOURCES.md`, and `docs/ARTIFACTS.md`; reconcile remote, local, and artifact state before acting. Chat memory is not shared between sessions; durable project files are the continuity source.
- Make routine, reversible project edits and host-side checks autonomously inside the repository. Keep physical-device changes, purchases, repository visibility changes, and unrelated account operations outside the CLI's authority. Do not run destructive commands, use full-access bypasses, or force-push.
- Preserve end-to-end responsibility: inspect diffs, run relevant checks, update evidence and checkpoint, and synchronize only through a verified authorized GitHub/Drive workflow. A CLI-generated local commit is not proof of remote synchronization.

- Target **Samsung Galaxy A10 SM-A105F**, historical SLK build **A105FDDS9CWB3**. Goal: genuine native Debian 13 Trixie `arm64`, minimal headless CLI userspace; no default GUI or Android chroot.
- Read `Prompt.md`, `START_HERE.md`, `docs/STATUS.md`, and `docs/JOURNAL.md` before new work. Update status and journal at milestones and handoffs with verified branch/commit, actual build/test results, blockers and next exact task.
- Source of truth for ordinary project files is the verified **private [SM-A105F GitHub repository](https://github.com/thamindudenuwarajayasinghe/SM-A105F)** on `main`. The pre-GitHub local commit chain is preserved in verified Drive bundles and has different ancestry from the remote source snapshot. Inspect remote before reconciling work; commit meaningful increments, inspect additions for secrets and private device data, then publish and verify without rewriting unrelated history. No source license is chosen yet.
- Record exact source URLs, revision or release, retrieval date, size, SHA-256, terms, and correspondence evidence in `docs/SOURCES.md`. Keep acquired inputs immutable; store large/private inputs and outputs outside Git and record location and hashes in `docs/ARTIFACTS.md`.
- Never claim a build, test, boot, safety property, or physical capability without actual evidence. A compiled kernel or emulated userspace is not device verification.
- Never modify the phone, flash, wipe, repartition, unlock/relock, or alter boot/security, identity or calibration partitions under this instruction. Obtain explicit approval for each consequential physical operation after validating exact target and recovery route.
- Protect charging and thermal behavior. Do not assume other A10 variants match this model. Check kernel bitness and device tree against exact stock evidence before boot packaging.
- Rootfs script syntax: `bash -n scripts/build-rootfs.sh`. Build preflight and requirements are in `docs/BUILD.md`; no rootfs build has succeeded yet. Current architecture and status are in `docs/ARCHITECTURE.md` and `docs/STATUS.md`.
- Archive tool checks: `python3 -m unittest discover -s tests -v` and `python3 -m py_compile scripts/inventory-archive.py`. They do not verify a real stock archive.
